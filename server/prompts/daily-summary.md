# 日终总结模板（给 agent 用，硬约束）

> 目的：日结只是**原材料**，不是知识。写得越短越好，知识单独提炼。

## 硬限制

- **≤ 15 行 / ≤ 400 字**，只写结果和结论，**不写过程**（不写"然后我又试了…"）
- 一天最多 3 条"做成了"，最多 3 条"结论/踩坑"，最多 2 条"留给下次"
- 每条一句话，能量化的写数（电压/转速/耗时/IP/版本）
- 日结**不进公共库**：只落自己的 source，slug 用 `daily/<YYYY-MM-DD>-<agent名>`

## 模板

```markdown
# <YYYY-MM-DD> <agent名> 日结

## 做成
- <一句话，带结果>

## 结论 / 踩坑
- <一句话结论>（前提：<型号/版本/现场>）

## 留给下次
- <一句话>
```

## 从日结里提炼「经验条目」再申请入库（一天 ≤ 3 条）

一条只讲一件事，四段固定，≤ 400 字：

```markdown
## <一句话标题：什么情况下怎么办>

- 适用前提：<品牌/型号/版本/阶段>
- 现象：<能一眼认出的特征>
- 结论/做法：<下次遇到直接照做>
- 证据：<实测数据 / 日志 / 截图位置；无证据就写"待验证">
```

提交：`curl -X POST <kb-web>/api/agent/capture`，`kind` 填 `经验`，只进「待确认」。
日结本身**不提交**，它作为"原件"留在自己的工作脑里。
